# Mercari Shops 上架准备流程

2026-10-18 起使用用户指定店铺的真实 Chrome 核对；2026-10-21 完成一次真实商品资料填写与下书き保存验证。范围为普通销售、单规格商品；预约和多规格表单另需人工设置。

| 平台字段 | 是否必填 | 本地资料来源 |
| --- | --- | --- |
| 商品图片 | 是，至少一张 | 在已收集图片中选取与本次商品一致的图片 |
| 日文商品名 | 是，最多 130 字符 | 日本选品标题 |
| 商品状态 / 成色 | 是 | 货源成色依据与图片；有厂瑕时不自动认定新品 |
| 商品分类 | 是 | 完整分类路径；已核对的商品类型可先生成建议 |
| 店铺库存 | 是，普通销售大于零 | 初始建议为 1，填写前确认实际可售数量 |
| 配送方式 | 是 | 通用上架设置 |
| 运费承担方 | 是 | 通用上架设置，注意平台可能锁定卖家承担 |
| 日本发货地区 | 是 | 通用上架设置 |
| 发货时效 | 是 | 通用上架设置 |
| 日元售价 | 是，300～9,999,999 日元 | 先带入日本参考价作为建议，填写前确认 |

商品说明、品牌、每单限购、JAN 码和商品管理码是可选项。系统按记录生成日文说明和管理码，不编造 JAN 码。品牌搜索结果需要人工核对，当前适配器会列为待处理项。

## 分类决定的专属字段

商品分类必须先从当前店铺分类树选择准确末级分类。Mercari Shops 可能随后显示这个分类专属的必填属性和选项；手办、衣服、相机等商品的属性表不同，不能复用同一套字段。

工作台已把分类属性作为 `category_attributes` JSON 保存到上架草稿。上架适配器选好分类后会读取当前页面实际出现的字段、必填状态和下拉选项，再按日文控件名或标签匹配资料包值。字段值可附 `source`、`evidence` 和 `source_url`，例如日本商品页给出的型号或中国货源明确写出的材质。命中且平台选项一致时自动填写；缺少来源证据、选项不一致或控件类型暂不支持时，任务结果会列出字段与可选项，避免用上一次手办资料或模型推测补值。

草稿编辑页的“分类专属属性”区域可保存这些有依据的值。准备资料时应先记录商品类型和关键属性；服装尤其要保存尺码 / 颜色 / 各自库存的规格矩阵。当前自动适配覆盖常见原生文本、数字、日期、下拉、单选和复选控件，复杂店铺组件与多规格变体尚未完成跨类别实测；**分类动态字段已接入基础扫描和映射，尚不能宣称所有品类自动上架已完成**。

## 通用设置

现有默认值为「らくらくメルカリ便」「送料込み（出品者負担）」「東京都」「4〜7日で発送」，手续费率 10%。用户可在“上架管理 → 通用上架设置”修改。默认值写入新草稿，历史草稿保留原值。

汇率、中国到日本运费、日本境内运费及其他成本用于内部核算，不是平台必填项。留空时保存为待核算；全部补齐后才计算利润。明确填写 0 和留空含义不同。

## 图片与货源

收图目标是至少 5 张不同图片，并包含实物图。参考图保留来源，不能证明供货商有货，也不自动勾选为上架图。上架前逐张核对销售组合，避免把整套 91 张、其他等级卡或第三方库存图误当成 9 张组合的商品图。

本次三丽鸥卡片采用整套 91 张、11.90 元的货源，销售目标为日本 9 张 SR 组合。整套采购成本计入一组，不扣除剩余卡片价值。分类建议为「ゲーム・おもちゃ・グッズ > キャラクターグッズ > カード・フォト・ブロマイド」。货源注明“默认厂瑕”，成色保留待核对。

## 执行顺序

1. 人工确认同款货源与当前页面价格后，系统立即按日本选品、中国货源和通用设置生成规则版资料包并保存快照。打开“上架草稿”可查看每项资料的来源、缺项及生成时间；资料、图片或通用设置变化后，快照会标记为过期。
2. 在“采集与监控 → 新增定时任务”选择“自动整理上架资料”，设置至少 60 分钟的运行间隔和每轮处理上限。任务会批量刷新已核验且尚未创建店铺草稿的商品；重复运行时跳过证据未变化的资料包。任务在本应用运行期间执行，程序关闭期间不会运行。
3. 核对建议售价、初始库存、成色与图片，至少选择一张已确认属于本次销售组合的图片后，保存本地草稿。内部核算可稍后补充。
4. 首次登录时，在“连接 Shops”窗口点击“打开 CDP Chrome 登录窗口”，然后在新窗口人工登录。回到任务结果点击“已登录，连接店铺”，工作台会通过本机 CDP 验证店铺并接管会话。之后点击“填写店铺草稿”即可复用登录状态；登录过期或平台要求验证时再人工处理。
5. 任务先显示本次资料和图片，确认后才开始填写。**平台编辑时会自动保存草稿，查看或关闭部分菜单也可能生成空白草稿。**
6. 核对填写报告及店铺草稿列表中的标题、价格与图片；品牌等可选项可留作待处理，不阻断保存。正式发布由人在店铺完成。

“检查上架表单”只检查字段识别，不填写商品资料。真实 Chrome 使用独立任务标签，断开连接保留 Chrome 和用户标签。系统不导出登录 Cookie、密码或验证码。

## 已验证与待验证

资料生成和图片处理使用本地规则，不调用 AI。日本选品 Skill 已记录关键词发现与同行卖家网络扩展逻辑，但本地工作台定时采集器尚不具备自主执行该 Skill、递归扩展卖家网络或归并规范商品的能力。批量定时任务负责刷新资料包，不会替用户确认同款、选择有使用依据的图片或发布商品。以后若要把这些人工关口也自动化，需要先增加可靠的站点数据来源、授权接入和对应的核验规则。

已验证：后台直接连接真实 Chrome、指定店铺范围、普通商品表单字段读取；独立拦截表单中的成色/分类选择、配送下拉框、价格格式与保存草稿按钮；成本留空、补齐后重算及历史数据库迁移；真实店铺完成普通单规格商品资料填写、5 张图片上传和下书き保存，并在草稿列表核对标题及价格。

待验证：有真实订单时校验行解析。目前订单页默认筛选为待付款/待发货，空列表不代表历史上没有订单。预约和多规格自动填写尚不支持；商品来源库存真实性及正式发布流程也未在本次验证。

## 2026-10-21 真实店铺草稿填写验证

本次使用用户指定店铺验证普通商品的单规格填写和下书き保存。商品为 MINISO × Chiikawa × Sanrio 全 9 种手办，标题 `MINISO ちいかわ×サンリオキャラクターズ フィギュア 全9種 1BOX`，售价 ¥18,000，上传 5 张商品图片。在店铺“下書き”列表核对到标题和价格后确认保存成功。该商品只保存为草稿，没有公开。库存 1 是联调占位值，中国货源的可售库存尚未确认，不能据此发布。

本商品实际选择的分类路径是 `ゲーム・おもちゃ・グッズ > フィギュア > コミック・アニメ > その他`。分类菜单是逐层展开的树：`フィギュア` 和 `コミック・アニメ` 是中间分支，最后一层 `その他` 才是所选分类。旧资料中的 `キャラクター` 路径在当前分类树中不可用；开发时应从当前页面分类树读取并逐层确认最终标签，不能只把本地分类建议直接当成可提交的叶节点。

真实页面的可复用交互和校验规则：

- 表单编辑过程会自动保存；点击“下書きへ保存する”后会跳转到 `/products?tab=draft`。成功判定需要在草稿列表核对同标题商品行及价格，不能只依赖 Toast 通知，因为页面可能在 Toast 消失前跳转。
- 页面顶部堆叠的 Toast 通知会覆盖分类、成色等弹窗。菜单行有展开动画，动画期间坐标点击可能误选相邻项；等待目标项可见后，按唯一目标行触发点击，再等待下一层和最终已选标签。退出未完成的分类弹窗时也优先点击明确的触发器关闭，避免遮罩残留。
- 填写任务需要支持幂等续填：检查页面已有值，匹配则复用，不匹配再更新；上传图片前读取已选文件名，避免重试时重复添加。页面已存在的选项弹窗应先收起，再开始下一项操作。
- 品牌是可选字段。搜索不到或无法可靠确认品牌时，将其记为可选待处理项，不应阻断其余必填字段填写与草稿保存；JAN 码仍不能编造。
- 自动保存、表单检查或打开新增页可能留下空白草稿。任务应复用已打开的新增表单页，并在填写结束后核对最终店铺草稿，区分空白草稿和本次目标商品。

本次实现修正位于 `app/modules/mercari_listing/browser_adapter.py`：分类点击前等待唯一目标项并使用 DOM 事件触发，逐层等待并核对最终标签；选择分类后扫描专属字段并按有证据的属性值填入；填写时复用已有页面状态并避免重复图片；草稿保存结果同时识别页面跳转和列表商品行。独立表单测试覆盖分类字段成功填写、必填属性缺失和属性值无证据时拒绝自动填写；全量测试 `BROWSER_FORM_TESTS=1 python -m unittest discover -s tests -v` 共 59 项通过。

后续开发需保留的边界：店铺草稿“保存成功”不等于商品已发布；库存、成色和货源图片的真实性仍取决于中国来源核验。本次只验证了普通单规格商品，不代表多规格、预约销售、真实库存同步或正式发布流程已验证。
