# 日本选品

## 两条选品路径

日本选品有两种相互补充的发现模式：

- **关键词发现**：围绕品类、品牌、限定地区或具体型号搜索，寻找当前日本市场的商品候选。
- **同行店铺扩展**：从一件商品打开卖家主页，判断卖家是否持续经营中国相关商品；若证据充分，就系统采集其在售和已售商品，把商品组合扩展成待筛选候选，再从高价值商品继续发现其他卖家。

第二种不是多搜几个关键词，而是遍历“商品 → 卖家 → 店铺商品组合 → 新商品 / 新卖家”的关系网络。具体网络证据及当前实现边界见 [选品规则与实现现状](references/selection-criteria.md)。

## 目标

为后续中国找货提供可识别、来源清楚、价格与在售状态已核实的日本商品候选。选品不是单纯找高价商品：候选还应有足够明确的品牌、系列、型号、版本或组合信息，让后续能够判断中国页面是否为同款。不要把日本商品在售当作中国有货、可盈利或已获授权的证明。

## 工作方式

1. 先保留用户给出的商品主题、品牌、系列和硬性条件。需要在日本站搜索时，使用日本站买家实际使用的日语名称和变体词；中文词先映射到已核实的官方日文名或商品页面用词，不要只做逐字直译。由宽到窄构造多条搜索词，保留每条实际使用的查询，避免一个过度限定的长词漏掉结果。
2. 使用项目已接通的日本采集流程搜索关键词、指定商品或参考店铺。当前已实现 Mercari 公开商品页采集；其他站点即使出现在站点目录中，也要先验证采集器已接通，再承诺能搜索。
3. 对每条候选核对来源页、商品标题、价格、币种和售卖状态。项目当前价格硬门槛是 **大于 9,999 日元**，即最低 10,000 日元。关键词发现模式筛在售商品；同行店铺扩展模式中，已售商品也可以作为历史需求证据和找货种子，但必须标明“已售”，不能说成当前可买。未知价、币种不明或低于门槛的条目不能作为满足售价门槛的商品候选。不要用多规格页面的最低价代表目标规格价格。
4. 打开候选详情，尽可能从页面核实商品身份、版本/型号、规格或套装数量、成色、图片和卖家信息。还要提取后续分类和刊登所需的商品类型及关键属性：例如材质、型号、尺寸、颜色、容量、适用对象、版本、套装数量和服装尺码。只记录页面明确给出的值，并保留来源；页面没有给出的数据记为“未知”，不能根据缩略图、推测或同系列其他商品补写。将重复商品与重复卖家规范化并去重。
5. 关键词模式按“身份清晰度、当前在售与价格证据、后续在中国站可搜索性、页面实际可见的需求信号”排序。同行模式还要看店铺组合中的中国相关商品比例与多样性、相同商品是否反复售出、商品身份是否可准确归并。只有页面确实展示时才记录销量、收藏等信号；不得把标价或搜索排名单独解释成成交需求或利润。
6. 已售商品显示的价格只当作该条历史商品页的价格证据，除非平台明确显示成交额，否则不要称为实际成交价。若要制作可上架商品资料，还要查找该商品当前的日本价格参考，并完成中国货源阶段。
7. 在没有外部阻断时自主筛选候选并继续项目流程，不为常规筛选增加人工审批关口。证据不足时标记未知或风险；不满足售价门槛的条目可保留为网络探索节点，但不得混入满足门槛的合格商品列表。若用户要求自动找货，按项目流水线交接候选，不以“待人确认”作为默认结束状态。
8. 保存候选时保留原始商品链接、原标题、日元价格和参考图链接。把发现模式、搜索词或种子商品、卖家主页、采集时间、售卖状态、商品类型、已核实的规格/分类属性、排序依据与未知项写入备注；每个属性都要指向日本商品页或店铺 listing 证据，不要将推测写成商品事实。服装的尺码、颜色与各自库存应作为变体矩阵保存，不能压成一个标题或总库存。

## 项目内实现与边界

- 当前价格门槛在 `app/modules/japan_selection/mercari.py` 的 `MINIMUM_PRICE_JPY`、`has_eligible_jpy_price` 和 `filter_minimum_price` 中实现。若业务门槛变化，更新代码和测试，并同步本 Skill 的参考规则，避免两套门槛漂移。
- Mercari 采集通过公开页面 DOM / JSON-LD；搜索、商品和店铺任务接口见 `POST /api/japan/search`、`POST /api/japan/collect/item` 和 `POST /api/japan/collect/shop`。采集完成后，按证据自主决定导入索引，使用 `POST /api/automation/jobs/{id}/import`；导入前需遵守价格与去重规则。
- 商品详情采集会提取卖家主页链接、ID 和显示名，可直接交给店铺采集任务；店铺列表采集尚未实现递归卖家网络和独立已售历史分页，未验证的能力不能向用户承诺。
- 采集规则与当前站点接通状态见 [选品规则与实现现状](references/selection-criteria.md)。中国找货约束见项目的 [自动找货运行说明](../../../docs/自动找货运行说明.md)；不要在本阶段声称已确认中国货源。
- 选品 Agent 的候选输出必须把“商品身份”和“上架属性”作为同一份可追溯资料：先由商品类型决定煤炉分类，再用来源证据填写对应分类的字段。工作台目前还没有自动递归同行店铺网络的后端，也没有跨品类完整字段模型；Skill 能给开发 Agent 稳定执行规则，但不会让定时采集器自动拥有推理能力。
- 不绕过登录、安全验证、访问限制或平台保护。遇到验证页时停止该站点采集并说明状态，不能把错误页当作“没有候选”。

## 持续改进

Skill 不会训练或改变基础模型；它通过明确规则、项目工具和真实复盘来稳定改善每次选品。每轮将实际结果用于校准：例如中国站成功找到同款、因版本/规格不符失败、商品售罄、或用户指出搜索词与候选偏差。收到可验证的新经验后，更新参考规则中的对应条目，记录日期、证据和适用范围；不要因为单个特殊商品就改变通用硬门槛，也不要删掉已有条件而不说明原因。每次修改后检查规则仍与采集代码及测试一致。
